# Coexisting ICC and nclx — 2026-09-07

The parser retained only one colr representation. Primary items selected the
first property, while sample entries selected the last. The usual writer order
(nclx then ICC) lost the poster's ICC and the track's nclx matrix hint. Reversing
the two boxes changed behavior. A dual-property fixture executed red on missing
poster ICC (`dual-colr-before.log`; after fixing the test locator's eager
then_some subtraction). The final test uses the ICC from libavif's
paris_icc_exif_xmp.avif; the initial missing-profile reproduction used the
smaller RGB-tagged negotiation fixture.

The parser now retains ICC and nclx independently for primary items and color
sample entries. Existing color_info()/animation_color_info() prefer ICC when
both are present. New nclx_color_info()/animation_nclx_color_info() retain the
nclx representation separately, including the no-poster parser layout. Borrowed
and owned constructors share the selection. Deprecated eager AvifData carries
an additional nclx_color_info field through both eager read and conversion.

Managed frame conversion, AOM frame conversion and strip metadata share the
same CP/TC/ICC selection helper. nclx supplies CP/TC when present, otherwise
sequence-header values remain the fallback; ICC is retained independently.
Fallback matrix resolution consults nclx even when ICC is authoritative for RGB
color management. Legacy FFI conversion uses the same retained nclx hint and
now reports retained CICP/ICC metadata. The lightweight detect probe reports
both nclx values and ICC presence instead of mutually excluding them.
