# WEDGE MAP — size/crop-expanded RD gap vs libaom (2026-07-03)

**Program**: the entire RD-gap program so far (docs/RD_GAP_VS_LIBAOM.md) measured ONE
size class (1024px long edge, full frames). This program expands the measurement over
**size** (256/512/1024/2048-or-native long edge) and **local content** (c50 quadrant
crops) on imazen-26, to uncover where zenrav1e's current-best still-image config still
loses to libaom — each loss cluster ("wedge") is a candidate next mechanism or
hyperparameter-expert head (docs/FEATURE_HINTS_PLAN.md §E).

**Headline: the 1024 win is real and reproduces — and it decays monotonically with
size, disappears on the biggest content family, and hides quadrant-level losses of up
to +44..+120% inside globally-winning images.**

## The alignment property (why every cell joins to precomputed features)

The encode corpus was materialized with **exactly** the conventions of
`zenanalyze/examples/extract_features_imazen26_crops.rs` — the code that built the
canonical feature grid `/mnt/v/output/imazen-26-features/imazen26_features_2026-06-23.parquet`:

- crop windows `round(W·f)×round(H·f)` at tl/tr/bl/br computed on the NATIVE PNG;
- then Lanczos3 `resize_exact` to `round(dim·target/maxdim)`, sRGB space, image crate
  0.25.10 (identical lockfile version both sides), downscale-only (`target ≥ maxdim`
  ⇒ the `native` size_class);
- encode input = `to_rgb8()` of that result (the same buffer the features see).

**Join verification: 123/123 materialized cells found their
`(origin_path, crop_label, size_class)` parquet row; width/height EXACT on all 123;
recomputed zenanalyze features clean at rel-tol 1e-3 with 0 deviating cells.**

Materializer: `examples/wedge_corpus.rs`; corpus + `_MANIFEST.json` + checksums at
`/mnt/v/output/rd-gap-wedge-2026-07-03/` (90 MB PNGs, block storage; Tower mirror
sha-verified at `/mnt/tower/output/rd-gap-wedge-2026-07-03/`).

## Grid

- **Origins (K=16, train-only)**: k-means K=16 over the 94 usable zenanalyze features
  (full+native rows, canonical LSD origin split {0,2,4,6,8}=train, StandardScaler,
  `random_state=0`, centroid-nearest; `scripts/rd_gap/wedge_select_k16.py`). 10 content
  classes; 5/16 picks coincide with train26 K=24 (7050, 7052, 8196, 6606, 9118) —
  the zr-side continuity anchors against the qmdist-2026-07-03 sweeps.
- **Sizes (full crop)**: {256, 512, 1024, 2048-or-native-if-smaller} long edge,
  downscale-only. 1024 overlaps the existing program for continuity.
- **Crops**: c50_{tl,tr,bl,br} at size 1024 (native crop when the 50% window's maxdim
  ≤ 1024 — sub-1024 origins contribute local-content cells at their true scale).
- **Q grid**: coarse 6-point convention. zenrav1e `-Q{30,50,60,75,85,95}`; libaom
  cq {8,16,24,32,48,63} × formats {420,444} (frontier over formats). The deterministic
  cell cache makes re-densification cheap.
- **Arms** (123 files → 738 zr + 354 zr-paletteoff + 1476 cpu2 + 384 cpu0 = **2952
  cells, zero failures**):
  - `zr` — current-best: `cavif -s2 --depth 8` from **zenrav1e master tip 32477046**
    (Tune::Ssimulacra2 + per-SB delta-q boost 1.0 + QM-dist ratio + palette tool +
    skip-recon/filter-intra recon fixes) with `ZENRAVIF_TUNE=ssimulacra2
    ZENRAVIF_PALETTE=auto` via dev-only env passthroughs in a **private clone**
    `ravif--wedge` (ravif@9d2b97c; the shared ravif tree's patch slot stayed with the
    concurrent lfsharp session). Box output verified bit-identical to a local smoke
    encode (7052 q60 = 2646 bytes both ends).
  - `zr-paletteoff` — same binary, palette Off, 59-file fired-class subset (plots,
    screenshots, products) — isolates palette-Auto across sizes.
  - `cpu2` — aomenc 632172a4 `--cpu-used=2` (matched-speed baseline), all files.
  - `cpu0` — aomenc `--cpu-used=0` default tune, {512, top-size} full-crop subset.
  - butteraugli (pnorm3 + max) columns on for every cell.
- Box: `zenavif-sweep-2` (Hetzner ccx63, snapshot restore) — box-1 was saturated by a
  concurrent session's sweeps; arm-parallel boxes per the remote README.

## Per-size fixed overhead (bytes = α + β·px over each origin's full-crop ladder)

| arm | low-q α med | high-q α med |
|---|--:|--:|
| zenrav1e (q30→q95) | +1.7 KB | +15.8 KB |
| aomenc cpu2 (cq63→cq8) | +3.1 KB | +21.8 KB |

zenrav1e's resolution-independent overhead is **lower** than libaom's at both ends
(AVIF container fixed cost measured separately: **242 B**/file). **The 256px parity
is per-pixel RD behavior at small scale, NOT header/container overhead** — α is in
our favor. (α here folds true fixed cost + ladder nonlinearity; n=16 origins × 6 q.)

## Palette-Auto across sizes — detection dies under downscale

Auto-vs-Off BD (negative = palette wins) and q60 byte ratio, full crops:

| origin (class) | native | 512 | 256 |
|---|--:|--:|--:|
| 7052 plots | **−39.2%** (0.72×) | −2.0% (1.000×) | −9.8% (1.005×) |
| 7050 plots | −12.2% (0.96×) | −2.2% (1.001×) | +0.7% (1.000×) |
| 8464 screenshot (667px) | −13.2% (0.91×) | −2.1% (0.999×) | −3.5% (1.008×) |
| 8196 screenshot (1920px) | −5.4% (0.96×) | −0.1% @1024: +0.0 (1.001×) | +1.1% (0.996×) |
| 9908/9446 products | ~0 | ~0 | ~0 |

At 512 and below the q60 byte ratios collapse to ~1.000: **the AA-aware detection
(faithfully ported libaom conservatism) stops firing once Lanczos downscaling softens
screen-content edges** — even one downscale step (8196 native→1024) kills it. Small
±BD residues on ≤512 plots are flag-bit noise on 1-3 KB files. Consequence: the
small-size screen wedge gets NO palette rescue exactly where the size decay is worst
(compounding wedges #3 and #6). The zenanalyze palette gate (palette_density /
distinct_color_bins are precomputed) should replace the ported heuristic — it can see
"this WAS screen content before resampling".

## Ranked wedge list (owning-mechanism hypotheses)

Ranking blends BD medians, reach-failure ratios, family traffic share (web =
small-heavy; 9226 alone is ~32% of imazen-26), and feature correlations (spearman of
per-file BD vs cpu2 over the 117 feature-joined files; the loss surface is
low-entropy/few-colors/patchy-flat content: luma_histogram_entropy ρ=−0.75,
palette_density −0.71, distinct_color_bins −0.71, patch_fraction +0.67,
flat_color_block_ratio +0.60, grayscale_score +0.61).

1. **Saturated synthetic screens — aom's near-lossless floor is unreachable
   (fam 7000 grids).** 7050: zenrav1e needs **3.4–3.9× the bits of aomenc's WORST
   point (cq63-444)** and still scores ~0.4 ssim2 lower, on ALL 5 of its cells (BD is
   undefined — these "reach failures" were invisible to every BD-based sweep so far).
   7052 residual +86.6% BD at native even WITH palette (−39% from palette already).
   Owner: **intraBC** (the doc's known non-palette candidate; aom hits 0.0155 bpp @
   ssim2 94.5 with screen tools we lack) + coefficient-level RD on razor edges.
   Hyper-head: screen-content mode gate + Q-range extension (our q95 tops out at 1/4
   of aom's floor efficiency).
2. **fam 9226 AI product shots — the only family-level loss, at EVERY size (+13.7
   med, 3/13 wins; ~32% of corpus traffic).** 9908 (beauty bottle, smooth gradient
   background): +24.5 @1024-full, **+78.4 c50_br** (the pure-gradient corner);
   9446 activewear +9.6 c50_bl. This is the o_6629-class smooth-gradient
   coefficient-RD residual, now shown to be a whole content family. Owner: gradient/
   flat-region rate misallocation — per-image variance-boost strength + QM-discount
   strength (both measured inverted-U per-image; §E heads), per-SB delta_q from
   zenanalyze aq_map for the region version. Features: patch_fraction/
   flat_color_block_ratio positive corr — cheaply detectable.
3. **Size-conditional decay — parity at 256px (−1.15 med, mean +0.04, 9/7).**
   Monotone: −13.0 (1024) → −6.5 (512) → −1.15 (256). NOT container overhead (α is
   in our favor); it is per-pixel RD at small scale: the ss2-tune quality/QM curves,
   delta-q octile boost, and partition defaults were all fit at 1024 only. Owner:
   **size-conditional tune parameters** (curve offset by log-px) — the most direct
   hyperparameter-expert head, px is a free input. Re-fit the tune constants on the
   {256,512} slices of this dataset.
   **MEASURED 2026-07-03 (the isolation A/B ran — this owner hypothesis was mostly
   WRONG)**: leave-one-out mechanism arms × {256,512,1024} acquitted 4 of 5 tune
   mechanisms (qmcurves keeps −7.2 of its −8.8 win at 256; chromadq GROWS toward small;
   boost/lfsharp below the conviction floor) — re-fitting those constants below 1024
   would LOSE bits. The un-suspected QM-dist ratio was convicted (−3.48 → −0.96, high-q
   band flips positive ≤512) and its half-strength long-edge ramp SHIPPED
   (zenrav1e@b0098eb1: train +1.03/+0.87 @256/512 vs full, VAL +1.12/+1.00, butteraugli
   agreeing, conformance 180/180). Most of the decay is NOT tune-attributable — the
   tune-off baseline itself decays −1.13 → +4.17 vs cpu2 (train, 1024→256) — so the
   residual owner moves to non-tune small-px coding behavior. Record:
   benchmarks/hyperparam_size_decay_ab_2026-07-03.tsv + RD_GAP_VS_LIBAOM.md
   "Size-decay isolation A/B" + HYPERPARAM_FIRST_CUT rule-2 STATUS.
   **MEASURED 2026-07-03 (later — the NON-TUNE A/B ran; wedge #3 attribution is now
   COMPLETE)**: 9 arms over the default coding path (quality-keyed ravif gates, chroma,
   Tune::Psnr, composites) × {256,512,1024} × 16q, pre-registered rule, per-armed-cell
   conformance. NO coding default convicted — the residual decay is zr's
   content-adaptive layer FADING on downscaled renditions (Psychovisual metric +
   activity-scored segmentation worth 7.5 BD @1024 → 4.4 @256 via the psnr arm; seg
   alone 4.1 → 1.8) against aom's uniform keyframe toolset (coeff-opt trellis,
   filter_intra, resolution-keyed speed features). One ship-bar-passing lever landed
   byte-neutral: rdotx below 1024 (`ravif@bae4880` SMALL_PX_RDO_TX_LIVE, TRAIN
   +0.80/+0.88, VAL +1.44/+1.30 unanimous, vs-cpu2 val 256 +12.72→+9.22) — flip
   pending policy sign-off. Found along the way: zenrav1e#34 (TX_MODE_SELECT sliver
   gate, FIXED upstream 1dabba91) and zenavif#29 (ravif 420 non-conformant everywhere,
   OPEN). Owner hypothesis for the remaining fade: re-calibrate activity masking +
   segmentation scoring for small/dense content (px is a free hint input). Record:
   RD_GAP_VS_LIBAOM.md "Non-tune size-decay isolation A/B" +
   benchmarks/hyperparam_sizedecay_nontune_2026-07-03.tsv.
4. **5318-class doc/brochure mid-quality climb (+20.9 @1024-full).** aom-444 climbs
   ssim2 85→92 nearly free (0.40→0.98 bpp) while zr's ladder pays double (+49% at
   ssim2 90). Scale-specific (512 −4.3, crops −3.6, 256 +5.1 milder) — colored-line/
   text detail at exactly the 1024 rendition scale. Owner: chroma delta-q clamp /
   QM level curve overshoot on text+line 444 content; quant_survival_uv negative
   corr supports a chroma-side misprice. Head: per-image chroma delta-q offset.
5. **Quadrant wedges inside winning images — spread up to 61.7 BD points.** 1480
   nature: full −14.6 but c50_tr **+43.7** (sky/cloud gradient quadrant); 8464 c50_tr
   +18.6; 7080 c50_tr +18.3; 9446 c50_bl +9.6. A global per-image knob cannot fix a
   quadrant — this is the direct case for **per-SB hints** (FEATURE_HINTS §B):
   region-local delta_q/λ from the zenanalyze aq/variance maps. (c50_tr median −4.3
   vs c50_bl −12.3 across origins is content — skies live top-right of these picks —
   not a directional encoder bug.)
6. **Palette detection dies under downscale (§ above).** Native-only wins; Auto==Off
   at ≤512 on resampled screen content (byte ratio 1.000). Owner: zenanalyze-picker
   palette gate replacing the ported AA-aware heuristic (the doc already tracks
   "detection threshold tuning / picker head" — now with the size axis quantified;
   also inherits libaom's 7058/8196-class rejections at native).
7. **1400-nature crops (+8.5 med crops vs −14.6 full).** Instance of #5 with a
   texture/sky split: textured quadrants win big, smooth-sky quadrants lose big.
   Same per-region owner; also the strongest single-image evidence that our
   activity masking over-spends on texture relative to aom (bl wins, tr loses).
8. **8100 screenshots below ~700px (+1.95 @256; 8464-native-667 +1.6).** Small text
   + no palette (#6) + size decay (#3) compound. Owner: size×screen-content
   conditional head; candidate quick win = palette gate that fires on downscaled
   screenshots.
9. **6000 patents @512 (+3.1, the family's only loss size).** 1-bit-scan line art
   at 512 — same synthetic-edge small-size regime as #3/#8; watch, don't own yet.
10. **7000 crops split (+8.9 med crops, 4/7 losses).** The plot quadrants that lose
    are the ones whose local structure the palette detector rejects at crop scale —
    #1 + #6 interacting below image level.

**Wins to protect** (do NOT regress while chasing wedges): 6600 scans-illustrations
(−22.7, 8/8), 9094 AI illustrations (−16.0, 16/16), 1200 interiors / 2000 people
(−12.7/−13.0, 16/16 combined), and the entire 1024 photo slice (−13.0 med).
